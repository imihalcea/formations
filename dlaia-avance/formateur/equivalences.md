## Conséquences pour le support

Les deux outils appellent `claude-sonnet-4-6` par Amazon Bedrock avec les identifiants du rôle de la VM : aucune clé à saisir, aucune commande de connexion dans les énoncés. Sous Claude Code, `/logout` et la recherche web sont indisponibles sur Bedrock ([CC amazon-bedrock](https://code.claude.com/docs/en/amazon-bedrock#3-configure-claude-code)). La section « À vérifier sur la VM » de `formateur/fil-rouge.md` donne les commandes de contrôle.

Avec Sonnet 4.6 sur Bedrock, Claude Code démarre en mode Manual, pas en `auto` : les énoncés n'ont pas à imposer `--permission-mode default`, et les demandes de permission apparaissent d'elles-mêmes. Le fil rouge autorise d'avance `uv run pytest *` et les scripts `.specify/scripts/bash/*` dans les deux outils, pour que les commandes Spec Kit s'enchaînent sans interruption ; toute autre commande et toute édition sont demandées.




Nouvelle conversation entre deux tâches : `/clear` sous Claude Code, `/new` sous Open Code.

Open Code n'a pas d'équivalent de la mémoire automatique, de `/context` ni des règles par chemin. Le module 7 les présente pour Claude Code et signale l'absence.
