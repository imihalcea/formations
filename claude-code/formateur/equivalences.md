# Équivalences Claude Code et Open Code

Documentation consultée le 17 octobre 2026 : [Claude Code](https://code.claude.com/docs/en/) et [Open Code](https://opencode.ai/docs/). Chaque ligne cite la page qui l'établit. « Non documenté » signifie que les pages consultées ne disent rien du point : il reste à vérifier sur la VM avant d'en parler en salle.

## CLI, session, permissions

| Fonctionnalité | Claude Code | Open Code | Sources |
|---|---|---|---|
| Session interactive | `claude` dans le répertoire du projet ; `claude "prompt"` pour démarrer avec une demande | `opencode` dans le répertoire du projet, ou `opencode <chemin>` | [CC cli-reference](https://code.claude.com/docs/en/cli-reference#cli-commands), [OC cli](https://opencode.ai/docs/cli/#tui) |
| Non interactif | `claude -p "prompt"` ; `--output-format text\|json\|stream-json`, `--max-turns`, `--permission-mode`, `--model` | `opencode run "prompt"` ; `-m`, `--agent`, `-c`, `--format default\|json`, `--auto` | [CC cli-reference](https://code.claude.com/docs/en/cli-reference#cli-flags), [OC cli](https://opencode.ai/docs/cli/#run-1) |
| Modèle au lancement | `claude --model claude-sonnet-4-6` | `opencode -m anthropic/claude-sonnet-4-6` | [CC cli-reference](https://code.claude.com/docs/en/cli-reference#cli-flags), [OC cli](https://opencode.ai/docs/cli/#flags), [OC models](https://opencode.ai/docs/models/#loading-models) |
| Modèle en session | `/model claude-sonnet-4-6`, enregistré par défaut pour les sessions suivantes | `/models` ouvre un sélecteur (`ctrl+x m`), sans argument documenté | [CC commands](https://code.claude.com/docs/en/commands), [OC tui](https://opencode.ai/docs/tui/#models) |
| Modèle dans la configuration | `"model": "claude-sonnet-4-6"` dans `settings.json` (utilisateur, projet ou local), ou variable `ANTHROPIC_MODEL` | `"model": "anthropic/claude-sonnet-4-6"` dans `opencode.json` (projet) ou `~/.config/opencode/opencode.json` | [CC settings-reference](https://code.claude.com/docs/en/settings-reference#model), [OC models](https://opencode.ai/docs/models/#set-a-default) |

| Modes de permission | `default` (affiché « Manual »), `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions` ; `Shift+Tab` fait défiler `default`, `acceptEdits`, `plan` ; mode de départ par `--permission-mode` ou `permissions.defaultMode` | aucun mode nommé : agents primaires Build et Plan, permutés par `Tab` ; `--auto` approuve tout ce qui n'est pas explicitement refusé | [CC permission-modes](https://code.claude.com/docs/en/permission-modes), [OC permissions](https://opencode.ai/docs/permissions/#auto-mode), [OC agents](https://opencode.ai/docs/agents/#primary-agents) |
| Règles de permission | `permissions.allow`, `ask`, `deny` dans `settings.json`, syntaxe `Outil(motif)` comme `Bash(uv run pytest *)` ; évaluation deny, puis ask, puis allow ; `/permissions` en session | clé `permission` dans `opencode.json`, valeurs `allow`, `ask`, `deny` par outil (`edit`, `bash`, `webfetch`…) et par motif de commande (`"git *": "allow"`) ; la dernière règle qui correspond l'emporte ; presque tout est `allow` par défaut | [CC permissions](https://code.claude.com/docs/en/permissions#manage-permissions), [OC permissions](https://opencode.ai/docs/permissions/) |
| Lecture seule, planification | mode `plan` : `Shift+Tab`, préfixe `/plan`, ou `--permission-mode plan` | agent `plan` (touche `Tab`) : modifications et commandes bash à `ask` | [CC permission-modes](https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode), [OC agents](https://opencode.ai/docs/agents/#use-plan) |
| Reprise de session | `claude -c` (dernière session du répertoire), `claude -r` (sélecteur), `/resume` | `opencode -c`, `opencode -s <id>`, `/sessions` (alias `/resume`) | [CC sessions](https://code.claude.com/docs/en/sessions#resume-a-session), [OC cli](https://opencode.ai/docs/cli/#flags), [OC tui](https://opencode.ai/docs/tui/#sessions) |
| Répertoire de travail | accès au répertoire de lancement ; `--add-dir`, `/add-dir` ou `permissions.additionalDirectories` pour en ajouter | répertoire de lancement ; hors de lui, permission `external_directory` (`ask` par défaut) ; aucun équivalent de `--add-dir` | [CC permissions](https://code.claude.com/docs/en/permissions#working-directories), [OC permissions](https://opencode.ai/docs/permissions/#external-directories) |

## Conséquences pour le support

Depuis la v2.1.283, Claude Code démarre en mode `auto` dans le terminal ([CC permission-modes](https://code.claude.com/docs/en/permission-modes)) : un second modèle valide les actions à la place de l'utilisateur. Le TP 2 fait lancer `claude --permission-mode default --model claude-sonnet-4-6` pour que les demandes de permission apparaissent.

Les stagiaires utilisent Open Code avec une clé API Anthropic. La documentation d'Open Code signale qu'Anthropic interdit les plugins qui utilisent un abonnement Claude Pro/Max ([OC providers](https://opencode.ai/docs/providers/#anthropic)).

Un seul fichier de contexte sert aux deux outils : Open Code lit `CLAUDE.md` en l'absence d'`AGENTS.md`, et Claude Code lit `AGENTS.md` en l'absence de `CLAUDE.md`. Le TP 5 fait écrire un `CLAUDE.md`, que `/init` d'Open Code nommerait `AGENTS.md` : l'énoncé fait renommer ou choisir un seul fichier.

Open Code n'a pas d'équivalent de la mémoire automatique, de `/context` ni des règles par chemin. Le module 5 les présente pour Claude Code et signale l'absence.

Au TP 6, la slash command et le skill ont un équivalent direct, et Open Code lit aussi `.claude/skills/`. Le hook diffère. Pour le formatage, la clé `formatter` suffit, avec la commande `["uv", "run", "ruff", "format", "$FILE"]`, car `ruff` n'est pas dans le `PATH` hors de `uv run`. Pour lancer `pytest`, il faut un plugin sur `tool.execute.after`. La documentation d'Open Code n'en donne aucun exemple ni la forme de ses arguments : le corrigé de ce plugin s'écrit et se teste sur la VM.

## À vérifier sur la VM

- `opencode models anthropic` liste `claude-sonnet-4-6`. La documentation d'Open Code ne cite pas cet identifiant ; il figure dans le catalogue [models.dev](https://models.dev/api.json) dont Open Code tire ses modèles.
- La version de Claude Code installée sur les postes : la lecture d'`AGENTS.md` exige la v2.1.277, le démarrage en mode `auto` date de la v2.1.283.
- Le mode de connexion d'Open Code avec la clé API : `/connect`, `opencode auth login`, ou variable `ANTHROPIC_API_KEY`. La documentation d'Open Code ne mentionne pas cette variable.
- Le plugin Open Code qui lance `pytest` après une modification.
