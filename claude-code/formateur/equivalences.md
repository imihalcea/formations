# Équivalences Claude Code et Open Code

Documentation consultée le 17 octobre 2026 : [Claude Code](https://code.claude.com/docs/en/) et [Open Code](https://opencode.ai/docs/). Chaque ligne cite la page qui l'établit. La documentation d'Open Code décrit la v1 ; quand le code du tag [v2.0.26](https://github.com/anomalyco/opencode/blob/v2tree/v2.0.26), installé sur la VM, la contredit, la ligne suit le code et cite son fichier. « Non documenté » signifie que les pages consultées ne disent rien du point : il reste à vérifier sur la VM avant d'en parler en salle.

## pandoc et WeasyPrint (module 7)

Testé le 18 octobre 2026 dans les images Docker `ubuntu:22.04` et `ubuntu:24.04`, avec `apt-get install pandoc weasyprint` :

| Distribution | pandoc | WeasyPrint | Python |
|---|---|---|---|
| Ubuntu 22.04.5 | 2.9.2.1 | 54.1 | 3.10.12 |
| Ubuntu 24.04.5 | 3.1.3 | 61.1 | 3.12.3 |

Sur les deux versions, `pandoc rapport.md -s --template template.html --css rapport.css --toc --pdf-engine=weasyprint -o rapport.pdf` produit le PDF attendu : table des matières, tableau, accents, saut de page par `break-before: page` et pied de page `counter(page) / counter(pages)` dans `@page`. `weasyprint rapport.html rapport.pdf` donne le même résultat depuis le HTML. Les paquets des dépôts suffisent : l'installation depuis les releases officielles n'est pas nécessaire.

Un PDF demande `--pdf-engine=weasyprint` : sans lui, pandoc passe par LaTeX ([pandoc, Creating a PDF](https://pandoc.org/MANUAL.html#creating-a-pdf)). `--css` exige `-s`, que `--template` implique ([pandoc, `--css`](https://pandoc.org/MANUAL.html#option--css), [`--template`](https://pandoc.org/MANUAL.html#option--template)). Pandoc 3.1.3 coupe les lignes longues du HTML à 72 colonnes, y compris le `<title>`, et WeasyPrint 61.1 ne garde alors que la première ligne dans le titre du PDF : `--wrap=none` l'évite ([pandoc, `--wrap`](https://pandoc.org/MANUAL.html#option--wrap)).

Sur le poste du développeur, pour la variante Claude Code : macOS, `brew install pandoc weasyprint` ; Linux et WSL Debian ou Ubuntu, `sudo apt install pandoc weasyprint` ; Windows, `winget install --source winget --exact --id JohnMacFarlane.Pandoc` et l'exécutable WeasyPrint des [releases GitHub](https://github.com/Kozea/WeasyPrint/releases), que des antivirus signalent parfois à tort ([pandoc, Installing](https://pandoc.org/installing.html), [WeasyPrint, First steps](https://doc.courtbouillon.org/weasyprint/stable/first_steps.html)). Pour que Claude Code lise un PDF de plus de 10 pages, `pdftoppm` (paquet `poppler-utils`) doit être installé.

## Conséquences pour le support

Depuis la v2.1.283, Claude Code démarre en mode `auto` dans le terminal ([CC permission-modes](https://code.claude.com/docs/en/permission-modes)) : un second modèle valide les actions à la place de l'utilisateur. Le TP 2 fait lancer `claude --permission-mode default --model claude-sonnet-4-6` pour que les demandes de permission apparaissent.

Les stagiaires utilisent Open Code avec une clé API Anthropic. La documentation d'Open Code signale qu'Anthropic interdit les plugins qui utilisent un abonnement Claude Pro/Max ([OC providers](https://opencode.ai/docs/providers/#anthropic)).

Open Code v2.0.26 ne lit que `AGENTS.md` (constaté en local le 18 octobre 2026 : un `CLAUDE.md` seul est ignoré, même cité dans `instructions`), et Claude Code lit `AGENTS.md` en l'absence de `CLAUDE.md` : un fichier commun aux deux outils s'appelle `AGENTS.md`. Au TP 5, chaque outil garde le fichier que crée son `/init` (`CLAUDE.md` ou `AGENTS.md`), sans renommage.

Open Code n'a pas d'équivalent de la mémoire automatique, de `/context` ni des règles par chemin. Le module 5 les présente pour Claude Code et signale l'absence.

Au TP 6, le stagiaire observe des extensions fournies. La slash command a un équivalent direct dans `.opencode/commands/`. Le skill de migration vit dans `.claude/skills/`, que lit aussi Open Code, mais il s'y invoque par `@schema-migration` et non par `/schema-migration`. Le hook diffère. Pour le formatage, la clé `formatter` suffit, avec la commande `["uv", "run", "ruff", "format", "$FILE"]`, car `ruff` n'est pas dans le `PATH` hors de `uv run`. Pour lancer `pytest`, il faut un plugin. La VM a Open Code v2, dont l'API de plugin diffère de celle que décrit la documentation (v1) : export `default` avec `id` et `setup`, puis `ctx.tool.hook("execute.after", …)`, d'après le source de la v2.0.26 ([anomalyco/opencode](https://github.com/anomalyco/opencode/tree/v2.0.26/packages/plugin/src)). Une première version testée en local est dans `tp/tp06/extensions/.opencode/plugins/run-tests.js`. Le refus d'éditer `uv.lock` n'a pas besoin de plugin : la règle `"edit": {"*": "ask", "uv.lock": "deny"}` suffit, car la ressource d'une édition est le chemin relatif au projet et la dernière règle qui correspond l'emporte ([`file-access.ts`](https://github.com/anomalyco/opencode/blob/v2.0.26/packages/core/src/file-access.ts), [`permission.ts`](https://github.com/anomalyco/opencode/blob/v2.0.26/packages/core/src/permission.ts)). Constaté le 18 octobre 2026 : l'édition échoue avec `Permission denied: edit`, même avec `--auto`.

Au TP 7B, le Makefile appelle `claude -p "/faits-marquants" < build/agregats.json`. Pour Open Code, il envoie le corps de `.opencode/commands/faits-marquants.md`, sans son frontmatter, avec les agrégats sur l'entrée standard : `opencode run -m anthropic/claude-sonnet-4-6 "<corps>" < build/agregats.json`. La réponse seule sort sur stdout, les traces de l'agent sur stderr. Corrigé dans `tp/tp07-pandoc/corrige-7b/`.

## À vérifier sur la VM

- `opencode models anthropic` liste `claude-sonnet-4-6`. La documentation d'Open Code ne cite pas cet identifiant ; il figure dans le catalogue [models.dev](https://models.dev/api.json) dont Open Code tire ses modèles.
- La version de Claude Code installée sur les postes : la lecture d'`AGENTS.md` exige la v2.1.277, le démarrage en mode `auto` date de la v2.1.283.
- Le mode de connexion d'Open Code avec la clé API : `/connect`, `opencode auth login`, ou variable `ANTHROPIC_API_KEY`, que le code v2.0.26 lit.
- Le plugin Open Code qui lance `pytest` après une modification.
- Avec le `opencode.json` du fil rouge (`"bash": "ask"`), `uv run pytest` demandé à Open Code déclenche une demande de permission.
- La distribution de la VM : Python 3.10 correspond à Ubuntu 22.04, hypothèse des tests pandoc et WeasyPrint ci-dessus. Les stagiaires doivent pouvoir lancer `sudo apt install pandoc weasyprint`.
- Avec `"edit": "ask"`, une édition demandée à Open Code affiche son diff avant acceptation, et l'agent Plan refuse toujours les éditions : si les règles du projet passent après celles de Plan, `ask` remplacerait son `deny`.
