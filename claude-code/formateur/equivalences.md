# Équivalences Claude Code et Open Code

Documentation consultée le 17 octobre 2026 : [Claude Code](https://code.claude.com/docs/en/) et [Open Code](https://opencode.ai/docs/). Chaque ligne cite la page qui l'établit. La documentation d'Open Code décrit la v1 ; quand le code du tag [v2.0.26](https://github.com/anomalyco/opencode/blob/v2tree/v2.0.26), installé sur la VM, la contredit, la ligne suit le code et cite son fichier. « Non documenté » signifie que les pages consultées ne disent rien du point : il reste à vérifier sur la VM avant d'en parler en salle.

## Conséquences pour le support

Depuis la v2.1.283, Claude Code démarre en mode `auto` dans le terminal ([CC permission-modes](https://code.claude.com/docs/en/permission-modes)) : un second modèle valide les actions à la place de l'utilisateur. Le TP 2 fait lancer `claude --permission-mode default --model claude-sonnet-4-6` pour que les demandes de permission apparaissent.

Les stagiaires utilisent Open Code avec une clé API Anthropic. La documentation d'Open Code signale qu'Anthropic interdit les plugins qui utilisent un abonnement Claude Pro/Max ([OC providers](https://opencode.ai/docs/providers/#anthropic)).

Open Code v2.0.26 ne lit que `AGENTS.md` (constaté en local le 18 octobre 2026 : un `CLAUDE.md` seul est ignoré, même cité dans `instructions`), et Claude Code lit `AGENTS.md` en l'absence de `CLAUDE.md` : un fichier commun aux deux outils s'appelle `AGENTS.md`. Au TP 5, chaque outil garde le fichier que crée son `/init` (`CLAUDE.md` ou `AGENTS.md`), sans renommage.

Open Code n'a pas d'équivalent de la mémoire automatique, de `/context` ni des règles par chemin. Le module 5 les présente pour Claude Code et signale l'absence.

Au TP 6, la slash command et le skill ont un équivalent direct, et Open Code lit aussi `.claude/skills/`. Le hook diffère. Pour le formatage, la clé `formatter` suffit, avec la commande `["uv", "run", "ruff", "format", "$FILE"]`, car `ruff` n'est pas dans le `PATH` hors de `uv run`. Pour lancer `pytest`, il faut un plugin. La VM a Open Code v2, dont l'API de plugin diffère de celle que décrit la documentation (v1) : export `default` avec `id` et `setup`, puis `ctx.tool.hook("execute.after", …)`, d'après le source de la v2.0.26 ([anomalyco/opencode](https://github.com/anomalyco/opencode/tree/v2.0.26/packages/plugin/src)). Une première version testée en local est dans `tp/tp06/.opencode/plugins/run-tests.js`.

## À vérifier sur la VM

- `opencode models anthropic` liste `claude-sonnet-4-6`. La documentation d'Open Code ne cite pas cet identifiant ; il figure dans le catalogue [models.dev](https://models.dev/api.json) dont Open Code tire ses modèles.
- La version de Claude Code installée sur les postes : la lecture d'`AGENTS.md` exige la v2.1.277, le démarrage en mode `auto` date de la v2.1.283.
- Le mode de connexion d'Open Code avec la clé API : `/connect`, `opencode auth login`, ou variable `ANTHROPIC_API_KEY`, que le code v2.0.26 lit.
- Le plugin Open Code qui lance `pytest` après une modification.
- Avec le `opencode.json` du fil rouge (`"bash": "ask"`), `uv run pytest` demandé à Open Code déclenche une demande de permission.
- Avec `"edit": "ask"`, une édition demandée à Open Code affiche son diff avant acceptation, et l'agent Plan refuse toujours les éditions : si les règles du projet passent après celles de Plan, `ask` remplacerait son `deny`.
